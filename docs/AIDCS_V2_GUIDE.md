# AIDCS 2.0 (AI Display Control System): Advanced Developer Guide

AIDCS is a massive leap forward in frontend AI orchestration. Instead of injecting a generic chatbot widget onto your site, AIDCS attaches locally to your DOM, reads the page semantically, maps all capabilities using rigid JSON rules, and delegates intelligence across multiple specialized AI Agents.

---

## 🌟 Key Features

### 1. Zero-Dependency Multi-Agent Orchestration
AIDCS natively groups intelligent behavior into explicit roles:
- **Content Agent (The Eyes):** Pulls structure directly from the raw DOM.
- **Voice Agent (The Ears & Mouth):** Sits in the UI Panel to stream user audio in real-time.
- **Navigation Agent (The Legs):** Routes users to target pages cleanly based on intent mapping.
- **Supervisor Agent:** Overrides behaviors safely for maximum security.

### 2. Edge JSON Caching (Zero-Shot Latency)
The Content Agent natively extracts hard HTML table numbers and DOM strings into a background JSON object without relying on LLMs. When a user asks a simple data question (e.g., *"What is my revenue?"*), AIDCS serves the answer in ~10 milliseconds straight from the local cache.

### 3. Bidirectional WebSocket Voice Streaming
No more waiting for AI to "think" before it starts talking. Using `websocket_audio_stream`, Google Text-to-Speech pumps audio chunks seamlessly the absolute millisecond the LLM returns its first text token.

### 4. Semantic Intent Navigation
The Navigation agent doesn't just read `href` elements. Using the `navigate_via_content_summary` function, it takes the semantic intent generated by the Content Agent (e.g., *"The user is looking at security logs"*), and autonomously redirects the UI to the correct route securely.

### 5. Instant Admin API Expansion 
Administrators can easily add new active Agents to the architecture via the Admin Dashboard. New parameters, API Keys, and specific section roles (`AI-44-AGENT_MGMT`) can rapidly scale the intelligence scope entirely via standard API JSON workflows.

## 🚀 Installation & Bootstrapping

Because AIDCS handles everything natively inside standard Javascript, installing it into your existing React, Vue, or Vanilla JS website is remarkably simple. 

### Step 1: Install the Package
First, pull the `aidcs-core` into your project without carrying mandatory external dependencies:
```bash
npm install aidcs-core
```

### Step 2: The Setup Wizard Portal (`/aidcs`)
Once the package is installed and your application runs, AIDCS natively exposes a configuration Web UI accessible at `yourdomain.com/aidcs`.

The Setup Portal allows system administrators to easily configure the AI environment globally before end-users ever interact with it. From this view, you can:
- **Set Security & Privacy Permissions:** Toggle boundary constraints dictating where the Agents can pull answers from. For example, selecting `Local Web Data Only` explicitly disables the LLM from making outside internet searches, forcing it to stick strictly to local content.
- **Enable/Disable Granular Modules:** Turn off individual features per agent if they are not needed.
- **API Key & Resource Tracking:** Input your API keys and track live, real-time token/cost usage via the integrated Dashboard charts.

### Step 3: Bootstrap the Root Element!
In your main application entry point (`index.tsx`, `main.ts`, or just a bare `<script>` tag), you must instantiate the engine natively to the highest DOM tree relative to your body.
```typescript
import { bootstrapAIDCS } from 'aidcs-core';

document.addEventListener("DOMContentLoaded", () => {
    // 1. Identify your website's primary root (e.g. your React mounting point)
    const rootElement = document.getElementById("root") || document.body;

    // 2. Supply configurations
    const aidcsConfig = {
      manifestPath: "/config/index.json",
      autoMountVoice: true
    };

    // 3. Mount the Supervisor Engine
    bootstrapAIDCS({ 
        root: rootElement, 
        config: aidcsConfig 
    });
});
```

## ⚙️ Advanced System Documentation

To actually make AIDCS work, you rely exclusively on your `registry/` and `config/` JSON files securely separated from your Javascript source logic. 

### Defining The Rootmap (`app-rootmap.json`)
HTML DOM structure means nothing to an AI. Instead of reading meaningless `div` classes like `<div class="p-4 mr-2">`, AIDCS needs you to label exactly *what* an element means logically.

Every actionable item is divided sequentially:
`AI-Section -> Subregion -> Component`
```json
{
  "id": "AI-41-USER_MGMT",
  "type": "user_table_section",
  "children": [
    { "id": "AI-411-ACTION_BAR", "type": "toolbar" },
    { "id": "AI-412-USERS_TABLE", "type": "table", "dom_selector": "#admin-users-table" }
  ]
}
```

### Locking The Functions (`app-function.json`)
The safest way to run LLMs on the actual presentation layer is to put them in a sandbox. The `app-function.json` locks what a specific Agent can do using strict section barriers. 

In this example, the `register_new_agent_api` is permanently locked. No user on the public login page (`AI-Sect-1-LOGIN`) can trick the LLM into executing this action because the DOM boundary rigidly blocks it.
```json
{
  "name": "register_new_agent_api",
  "description": "Calls the backend API to dynamically register a new AI agent",
  "allowed_sections": [
    "AI-Sect-4-DSP"
  ],
  "parameters": [ "agent_name", "api_key", "role" ],
  "dom_operation": "api_request"
}
```

### The Communication Orb UI 
For the user to converse, AIDCS requires a dedicated interface component (typically the glowing *AI Orb* or chat tray) embedded securely in mapping ID: `AI-Sect-5-AIC`.
When the Assistant Agent speaks, the WebSocket stream routes raw `Uint8Array` byte packets straight through the supervisor into the Orb’s visualizer module!

### Database Connectors
Admins can toggle standard backend logic right from their dashboards (`AI-45-DB_PERMISSIONS`). When toggled on, the engine authorizes the `grant_database_access` trigger, and the Content Agent will automatically sync complex structured tables asynchronously into its fast-cache arrays.

### 🌐 The Netzach Integration Hub (`AI-46-NETZACH_HUB`)
For teams lacking the time to manually train agents or the budget to handle raw API Keys, AIDCS seamlessly hooks into the overarching **Netzach Framework** via its core endpoint: `https://aidcs.netzachs.com/`.
- **Primary Registration:** A rigid registration form (`AI-4631-REGISTRATION_FORM`) handles onboarding. It extracts user details and requires mandatory structural approvals for Privacy Policies and Terms of Service agreements securely.
- **Pre-Trained Subscriptions:** Admins can instantly subscribe to specialized Netzach Agents natively. Upon a successful subscription loop, the engine automatically grants control panel access by securely redirecting the user to `https://aidcs.netzachs.com/{user_id}`.
- **Global Error Reporting:** If an AI agent hallucinates, runs out of memory, or encounters a DOM crash, the system leverages the universal `report_system_error` function. This silently captures the `error_payload` and POSTs it directly to the Netzach diagnostic hub at `https://aidcs.netzachs.com/error/{user_id}`.
- **Fine-Tuning API:** The system can export interaction logs via `connect_netzach_finetuning`, routing datasets to Netzach securely to dynamically fine-tune LLM models serving your specific application.
